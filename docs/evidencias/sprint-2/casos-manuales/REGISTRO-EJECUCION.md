## Cómo se ejecutó y qué límites tiene (leer antes de citar los resultados)

1. Interfaz: se manejó con Chrome headless usando el `puppeteer` que ya trae el repo, porque necesitaba guardar las capturas como archivos. Se verificó además en el navegador integrado de Claude que la aplicación carga y muestra el login en la misma instancia. Las capturas son tomadas en esta ejecución y no se editaron.
2. API: llamadas reales con `curl`; los archivos `.txt` guardan la solicitud, el código HTTP y la respuesta. Los tokens de sesión demo se reemplazaron por `<redactado>` en esos archivos. Eso es lo único que se tocó en las evidencias.
3. El frontend se compiló con `VITE_AUTH_BYPASS=true` para garantizar el modo demo y que no se llamara a Firebase real. En S2-CP02 se registró el tráfico de red: no hubo solicitudes fuera de `127.0.0.1`.
4. Se levantaron dos instancias del backend, ambas con datos en memoria y ya apagadas:
   - Instancia A (puerto 3000) sin proveedor de correo: casos S2-CP02 a S2-CP07, S2-CP08 (parte de cantidad cero), S2-CP10 (correo inválido y proveedor no configurado) y S2-CP11 a S2-CP16.
   - Instancia B (puerto 3001) con un proveedor de correo FALSO y local (HTTPS con certificado autofirmado, `NODE_TLS_REJECT_UNAUTHORIZED=0` solo en esa instancia, token ficticio). No envía nada a internet. Se necesitó para tener cotizaciones en estado "enviada", que en el código solo se alcanzan cuando un proveedor acepta el envío. Se usó en S2-CP08 (parte enviada), S2-CP10 (proveedor caído) y S2-CP17. Esto NO equivale a ejecutar S2-CP09.
5. Cosas que el entorno no permite validar y que no se deben declarar como validadas:
   - El OCR es simulado: devuelve siempre los mismos datos (valor 185.000, proveedor de ejemplo) sin leer la imagen. En S2-CP13 solo se valida la preparación de la imagen, la conservación del original y el flujo; no la calidad de lectura.
   - Los correos reales, Firebase real y MongoDB real no se probaron.
6. El backend debe iniciarse desde la raíz del repo para que sirva el frontend; iniciado desde `backend/` (como hacen `npm run preview` y `npm run start`) responde 403 (DEF-01). Para ejecutar los casos se arrancó con `node backend/app.js` desde la raíz.
7. Datos de prueba ficticios: cotización "Cliente QA Sprint 2", solicitudes de viaje con destinos "QA", comprobante sintético generado para la prueba (`S2-CP13-00-...png`), cuenta `qa.comercial@example.com`. Se reactivó la configuración `Cercha-6-12` después de S2-CP06 para no alterar los casos siguientes.
